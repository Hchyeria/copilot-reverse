Fix two bugs found by driving the real `pi` CLI against the daemon. `/openai/chat/completions` streams never emitted a terminal `finish_reason` chunk — they jumped straight from content deltas to the usage chunk and `[DONE]`, so a client that treats a missing `finish_reason` as a truncated response rejected every streamed reply ("Stream ended without finish_reason"); Codex never tripped on it because it drives `/responses`. Streams now close with a `finish_reason` choice chunk (mapping tool calls to `tool_calls`, as the non-streaming path already did) before usage and `[DONE]`. Separately, model discovery no longer corrupts model ids when it fails: the worker fired four concurrent `/models` requests for the same payload at boot, which Copilot serializes, so under a slow upstream all four raced the same 8s timeout and degraded together — and because the fallback list uses *dashed* ids that the router fuzzy-matches against, a valid `claude-opus-4.8` was rewritten to a nonexistent `claude-opus-4-8` and hard-failed with `400 model_not_supported`. Discovery is now a single fetch, and a failed one leaves the router with no list, passing the requested id through untouched.
